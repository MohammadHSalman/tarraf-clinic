# Validation — source 0.2.0, 2026-10-23

Completed successfully:
- flutter analyze / Dart analyzer: no issues.
- flutter test: 15 tests passed on actual SQLite through sqflite_common_ffi.
- flutter build bundle --debug --no-pub: exit 0, Dart/Flutter application bundle generated. This is not an APK or an Android native build.
- Standalone docs/schema.sql replayed successfully in SQLite 3.53.1, 15 STRICT tables, foreign_keys=1.

Tests cover: exact decimal parsing and integer consumption; UUID/STRICT/FK validation; immutable material rename/reprice with historical date/cost retention; archive selection rules; point/cost/revision rollback after an injected database failure; stale revision and mismatched batch rejection; accrual vs cash date separation; allocation ceilings and cross-patient rejection; voided receipt history; draft cascading deletion; legacy raw-record retention, timestamps, images, unknown costs, overpayment credit and migration idempotence; precision-failure migration rollback; AES-GCM authenticated-context substitution and wrong-key rejection; cross-key portable backup restoration including voided allocations and wrong backup passwords; Arabic PDF generation; multiple material lines and multi-session allocations without fee/cash duplication, including procedure/category filters.

Scope limits:
- FFI uses host SQLite to verify relational rules. The source-only run did not execute the Android driver; this limitation is superseded by the dated Android release validation below, while physical-device acceptance remains pending.
- No real patient data was provided. Migration tests use synthetic records, and the original legacy file is never deleted.
- Pinch/tap behavior, camera, face/fingerprint lock, OS notification scheduling, large-media performance and backup file activation under power loss still require Android device acceptance tests.
- Face/body SVGs are scalable documentation illustrations, not clinically validated anatomical treatment guides.
- Images remain encrypted within database payloads; large datasets still require pagination/streamed media optimization. No data-size benchmark is claimed.
- Historical legacy procedure metadata is preserved in encrypted session payloads and raw archives; not every legacy custom field has a dedicated editor in the new UI.
- Payment-status filters reflect current settlement, not as-of accounting. Operating expenses, refunds as a separate ledger, inventory stock control and multi-currency conversion are outside this release.
- Backup v2 has a new format. Existing installed 0.1.1 data migrates automatically after explicit currency setup; standalone v1 backup-file import is not silently treated as v2.

Native acceptance checklist before clinical use: signed in-place update over 0.1.1 with a password backup; successful/wrong-key migration; actual ciphertext inspection of SQLCipher files/WAL; camera/consent import; biometric failure/recovery; zoomed coordinate accuracy; notifications after device restart, migration and restore; low-storage/interrupt restore behavior; representative data-volume testing.
